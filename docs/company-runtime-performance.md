# 员工客户端的长任务数据与上下文

macOS 员工客户端使用 WebKit 显示 React 聊天页面，Python 运行时负责模型和工具调用。WebKit 是页面引擎；页面占用取决于传入的数据、保留的内容以及刷新频率。

## 实时事件

本地运行时在 JSONL 序列化之前投影 `state_update`、`state_snapshot`：只保留最近一条 AI 消息的输入用量和上下文组成。完整历史、图片、工具参数和其他图状态不再随状态事件重复进入 Go 和 WebKit。没有统计变化用途的状态可以省略。

正文、推理、工具调用、工具结果、附件以及结束/错误事件保持原来的内容和顺序。模型输入、任务检查点和最终持久化历史不受界面投影影响。

聊天状态仍依次接收每个增量，但连续文本、推理、工具参数和进程输出的订阅通知合并到每个动画帧一次。同步读取始终获得最新累计状态，工具结果、错误和结束立即刷新。未被订阅的会话不安排界面刷新；移除会话会取消待执行通知。重复或无效的上下文统计不会引发刷新。

这降低了大状态跨进程复制和页面重复渲染的负担，不构成对任意任务内存峰值的承诺。实际工具结果、图片和完整检查点仍然需要资源；检查点存储的保留策略属于独立的持久化问题。

## 自动上下文压缩

公司专家快照的 `model_profiles` 只传递模型的正整数容量字段：`max_input_tokens`、`context_window` 和 `max_output_tokens`。不包含供应商凭据。客户端结合专家输入上限和已配置的输出预算，向本地模型适配器提供容量，使现有 deepagents 压缩机制使用模型相关的比例阈值，通常在输入容量的 85% 左右触发，并保留近期消息。旧历史写入本地上下文归档，摘要与压缩位置进入检查点；完整会话记录继续持久化。

代理对已识别的供应商上下文超限返回稳定的 `company_model_context_overflow` 类别。客户端仅在尚未收到输出时将它恢复为 `ContextOverflowError`，让现有压缩中间件缩减请求并执行有界重试。普通参数错误、鉴权失败、取消以及已经输出部分内容的失败不走这条重试路径；不通过重新运行整项任务恢复，因此不会为压缩重放已完成的工具。

图片等内容的近似计数可能低于模型真实输入用量。客户端使用最近一次模型报告的输入量与该请求保存的组成估算，校准下一次请求的预算；达到容量的约 85% 时，在发送前触发压缩。压缩后的请求按缩小后的内容重新计算，避免旧统计导致反复压缩。

模型有时以 `finish_reason=length` 正常结束 HTTP 流，只产生思考内容而没有正文或工具调用。接近输入容量时，客户端将这种情况交给同一压缩机制做一次更小请求的恢复；不会再把空输出标为任务完成。已经产生正文、工具参数，或输入并未接近容量的输出截断会明确报错，不静默重放。无法进一步缩减或再次截断时停止并报告失败。

这项改动需要服务端和员工客户端都更新后才能完整生效。旧服务器没有模型容量元数据时，客户端优先使用专家配置的输入上限；两者都未知时仍使用现有的 128,000 token 回退值。管理员应准确填写本地模型容量。单次生成达到输出 token 上限与输入上下文超限是不同情况；本机制不会把所有截断或中断都自动重跑。

## 定向验证

`tests/unit/company_runtime/test_ui_stream.py` 覆盖大历史/图片投影和原始数据保留；`test_compaction.py` 覆盖容量传递、主动压缩、超限恢复、普通错误与部分输出隔离，并通过真实 harness、模型代理和 SQLite 检查点验证多次工具调用后自动压缩且文件写入仅执行一次。前端 `chatStore.streamNotifications.test.ts` 验证大量增量合并通知、同步读取、结束刷新及清理；关联的本地运行时、团队、审批和历史测试覆盖会话生命周期。
