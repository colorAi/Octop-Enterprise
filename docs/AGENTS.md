# 文档存放与公开规则

| 位置 | 读者与内容 | 分发范围 |
| --- | --- | --- |
| `docs/user/` | 员工和管理员：安装入口、功能操作、配置、升级、备份恢复和故障排查 | 公开 |
| `docs/developer/` | 开发者和维护者：当前架构、API、协议、源码构建和发行规范 | 公开 |
| `docs/developer/adr/` | 已定稿的架构决策，注明适用范围和历史状态 | 公开 |
| `docs/assets/` | 公开文档引用的图片和资源 | 公开 |
| `.internal/docs/plans/` | 需求草案、更新计划、实施步骤和待改造清单 | 仅本地 |
| `.internal/docs/reviews/` | 评审对话、模型评审、问题排查和修复过程 | 仅本地 |
| `.internal/docs/verification/` | 验收待办、测试运行记录、部署回执和本机证据 | 仅本地 |
| `.internal/docs/maintainers/` | 具体批次的发布安排、候选刷新和交付过程 | 仅本地 |

- `.internal/` 已被 Git 忽略，源码导出另行排除；禁止用 `git add -f` 将其加入公开仓库。既有内部设计记录归档在 `.internal/docs/design/`，新资料按上表存放。
- 新公开文档只能放在上述公开目录；`docs/` 根目录仅放索引和本规则。不要恢复旧的 `docs/design/`、`docs/internal/` 或 `docs/superpowers/`。
- 公开文档描述当前版本能做什么、如何操作和必要的限制。未来目标、PR 拆分、阶段安排、临时文件路径、个人机器记录和未完成清单放内部目录。
- 设计实现后，将已确认的用户行为整理到用户指南，将稳定接口和架构整理到开发者文档。内部原稿继续在本地保留。
- 用户启用某个功能所需的部署条件、命令、权限及排错步骤必须在用户文档中完整提供，不能要求用户阅读内部计划。
- 公开文档只能链接发行范围内的文件或可访问的外部资料。移动文档时更新相对路径、HTML 图片路径、README、内置帮助和工具输出中的引用。
- 社区二维码使用用户提供的原图，不重绘、不重新生成。记录刷新日期，有效期以图片标注为准。更新中英文 README 并归档不再引用的旧图。
- 文档修改运行相关的导出测试和完整公开文档链接检查；不因文档整理升级产品版本，也不要求构建应用安装包。
