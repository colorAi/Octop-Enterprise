# 员工客户端权限与功能配置更新

[English](client-config-update_EN.md)

本功能适用于服务端网页、Mac 和 Windows 企业员工客户端。首次独立发行版本为 `1.0.0`。

## 使用

- 管理员在用户管理中调整某位员工的角色、权限或策略后，保存会自动通知该员工。
- 调整模型授权或其他功能配置后，管理员可在左侧「管理 → 应用设置」中打开「应用更新」标签，在「员工客户端配置更新」区域填写可选说明，点击「通知客户端更新配置」。
- 员工收到「企业配置有更新」提示后，点击「更新配置」刷新当前界面；也可以选择「稍后」。程序和本地执行进程保持运行，不需要退出再启动。
- 新增授权的功能入口会补到菜单的默认分组中，兼容此前保存的菜单布局；手动隐藏的入口与原有排序仍保留。
- 服务端始终按当前权限校验请求。客户端收到变更时也立即同步角色与权限，延后刷新不会保留被撤销的权限。

现有客户端需要先安装一次包含此功能的新安装包。此后权限与配置更新可在运行中刷新。新界面代码、程序升级仍通过公司自己的构建与安装包发布流程交付。

## 刷新保护

任务执行或准备、等待工具审批、编辑本机消息、上传附件、未发送附件或排队消息、录音或转写、浏览器录制或回放等情况下，会提示完成当前操作后再刷新。文本草稿先同步保存；刷新保留当前站点的登录状态和已保存草稿。 本地状态中的已完成、失败、取消及待核对结果只是保留的任务回执，不会被当作正在执行的任务；无需清空历史记录即可更新。

优先复用已有 WebSocket 发送配置变更事件；断线重连、窗口恢复焦点以及可见页面每 30 秒检查一次作为补充。选择「稍后」后，同一版本的轮询不会反复弹出；下一次配置变更会再次提示。重新打开页面会直接读取最新配置。

## 实现边界

- `GET /api/client-config/status`：登录用户只读取自己的有效角色、权限、配置摘要与更新说明，响应禁止缓存，不返回私有策略值。
- `POST /api/client-config/publish`：仅管理员可发布，更新说明最多 500 字；发布记录写入已有 settings 表并留下审计事件，不变更数据库结构。
- `client_config_changed` 事件只通知客户端重新查询自己的状态，不携带其他员工信息。
- 桌面 `refresh_status` 只查询现有本地任务，不创建执行环境、不要求先配对项目，继续校验账号与 nonce 范围。
- 本功能不调用上游安装器、系统软件更新或服务重启接口。

## 验证范围

源码包含配置通知、任务保护和菜单授权的相关测试。每次发行应验证角色变更自动通知、管理员手动发布通知、忙碌时阻止刷新、草稿保留及新增菜单显示。安装包、签名、真实设备和部署验证结果按具体发行记录，不以某次开发测试结果代表后续版本均已验收。
