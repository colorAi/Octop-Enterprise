# 共享执行协议

本协议先于共享执行表实现，适用于网页、桌面、定时和审批恢复。数据库是任务、占用和命令的权威；进程中的 Future、锁和通知仅用于等待。

## 身份与状态

- 幂等键为 `(user_id, operation, request_key)`，请求比较规范 JSON 内容；相同键及内容返回原任务，相同键不同内容冲突。提交成功表示任务和会话占用已在同一事务提交。
- WebSocket 在进入渠道内存队列之前保存任务并返回持久事件；渠道处理和断线补读沿用同一个请求键。IM 平台消息编号按渠道及会话隔离；旧消息重投不能被误认为其审批表单的答案。steer 续接生成新的请求键。
- 会话占用以实际 `thread_id` 为唯一键，同时验证用户及专家。队列、审批等待、取消请求及结果未知都保留占用；只有明确终态释放。同一会话的新消息不能绕过已有桌面任务。
- `queued → running → completed | failed | cancelled | awaiting_approval | unknown`。`running/awaiting_approval → cancel_requested`；排队取消直接进入 `cancelled`。审批只接受绑定该任务和审批编号的一次决策，恢复同一任务。`unknown` 不自动重试；停止证明只允许解除进程归属，不代表外部副作用已经核对完成。
- 命令为 `pending → applied`，命令键在任务内唯一，载荷不一致冲突。取消确认只表示命令已持久化；执行者确认停止后才进入 `cancelled`。
- 运行归属为用户、节点启动代次、递增 fencing token。每次领取、步骤检查、事件、回执和完成写入同时验证节点、代次、token 及数据库时钟租约。失联后进入 `suspect`，不把租约过期当作可接管依据。

## 停止证明

部署监督者必须在数据库之外确认执行者及子进程已经终止：容器部署使用引擎检查同一容器 ID、节点标签、启动时间摘要、启动代次及 `State.Running=false`、非空结束时间。启动代次包含容器启动标识与 Python 进程随机标识，因此同一容器中第二次启动 Python 也不能冒用原代次。容器进程命名空间内的子进程随容器停止；独立沙箱容器必须逐个检查，既查询登记表，也按执行者标签发现创建成功但来不及登记的沙箱。

确认接口记录证据来源、容器身份和检查结果，拒绝用户提交的任意“已停止”布尔值。没有可验证证据时维持 suspect/unknown，不转交可写工作区。普通心跳、HTTP 失联、PID 不存在、租约超时、容器已被删除均不构成该证明。停止记录按节点和代次保留，新代次注册后仍可核对旧任务；未知任务还需提供每个未结算模型请求和工具操作的外部结果证据。

优雅排空先停止领取，等待活跃调用和子进程结束、关闭运行时，再退出容器。在线的空闲用户归属移交必须先卸载其运行时；不能仅因数据库中没有 running 任务就允许两个进程打开同一检查点。

## 事件、设备与额度

- 事件游标是任务内单调递增的 `seq`，事件键在任务内唯一。页大小和单事件字节数有上限，提交终态与终态事件在一个事务完成。通知只携带唤醒信号，断线后仍按游标补读。
- 网页接收的每个帧增加任务 ID、事件 seq 及批内 index，重连可从一个批次的中间继续；终态与最终 done 帧在历史写入结束后一起提交。
- 一个异步任务负责整条 Harness 流的读取与关闭，以保留跨帧 ContextVar；生产者缓冲最多 2 帧，事件提交按时间/字节数合并。IM 审批卡片带有持久暂停标识，审批与问答恢复原任务；命令提交后再更新本地卡片，连续相同审批也使用新的编号。
- 设备连接代次由数据库增加，工具操作具有独立操作 ID。发送前保存操作；旧连接回复被拒绝。连接丢失后已发送但无回执的操作保留 unknown，不能自动重发。
- 服务器任务与每用户队列上限由共享记录控制，领取按用户最近调度次序轮转。模型并发独立配置，`max_models=0` 默认不限制；只有管理员显式设置正数时才计入全局模型槽。API 与本地模型一致，不能用服务器内存档位推导上游并发。桌面活动模型请求不计入等待队列。额度仍先预留、后结算；进程失联保留未确认额度，不能因租约超时重复发放。
- 所有事务保持短小，等待模型、设备、审批、文件或网络时不持有数据库事务。关键权限每次从当前数据库及 Go 权威读取，不依赖进程内用户对象。

## 兼容和启用

沙箱总内存也由共享数据库准入：创建/启动前按容器完整 cgroup 上限预留，同一名称幂等、每次重新预留生成不同 token，旧句柄不能释放新一轮额度。初始化辅助容器和主沙箱串行启动，共用同一预留，辅助容器上限不超过该预留。数据库事务不包含 Docker I/O。Docker 错误、超时、失联和租约过期不释放预留；确认两个容器停止或监督者证明旧执行者和全部沙箱停止后才能释放。

预算不足提交短期回收信号并明确拒绝启动；其他 worker 可提前回收无持久任务、无活动引用的空闲实例，保留文件与历史。运行、排队、审批、取消中、unknown 的保护不变。模型/工具开始前的明确内存拒绝保存 failed 回执，HTTP 返回可重试 503；执行开始后的异常仍遵循 unknown 规则。停止证明须覆盖预留名称，兼容未包含预算表的旧 schema 29 执行者；新的 web/worker 要求完成预算初始化标记。

单体继续可用。分角色入口仅接受 PostgreSQL、已完成的一次性初始化和一致的共享执行协议版本。尚未接入共享占用的旧执行入口不能与新 worker 同时消费同一实例。任务恢复不得通过重发旧客户端消息实现；支持任务 ID 与游标的客户端补读已有结果。

运行时使用初始化保存的固定节点拓扑：员工按用户 ID 分片，管理员与匿名全局入口归排序后的首个节点。HTTP、WebSocket、设备首帧认证、工作区与执行领取使用相同归属；不可用的所有者不会被其他 worker 自动替代。`runtime-host` 约束仅用于全局协调、身份后台投递和源发布，普通用户运行时可分布在 1–3 个完整 worker。拓扑变化前必须停止全部旧 worker 及沙箱并记录证明，重新初始化后才重分片；固定命名卷保留内容，unknown 继续阻止同一会话重放。

空闲回收在生命周期锁和活动引用保护下卸载 Harness、关闭记忆并停止沙箱；保留归属、启用状态和数据。持久排队、运行、审批、取消中、unknown 或本地调用/维护/写入任一未结束时不回收。下一次访问重新获取工作区，不能复用已关闭的 IM 附件句柄。共享检查点 DDL 在 init 的迁移锁内预先完成，避免多个 worker 首次调用并发建表。

取消和审批为持久命令；原有 steer 队列没有获得故障后自动恢复语义。维护使用在线管理 API 和不执行迁移的 `octop execution`；普通离线/嵌入式 CLI 不允许绕过运行时修改已切换的执行域。部署、备份和回退见 [分角色指南](../../docker/enterprise/ROLES.md)。

## 群专家执行协议 v2（schema 36）

实施依据为[公司群邀请专家计划](company-group-experts-plan.md)。本节固定已接入的持久记录和两侧交互规则。Worker 只有装配群专家执行器后才以 `group_expert_protocol=2` 注册；默认和其他运行角色为 0，数据库迁移成功本身不代表群功能已启用。

### 准入、归属与控制

- 首版仅在 `execution.mode=distributed-v1` 的 PostgreSQL `web/worker` 部署启用。准入事务检查固定拓扑的所有 Worker 均存在、就绪、租约有效且声明协议 2；额外的未确认停止执行者、缺少节点、单体模式和未知能力均拒绝准入。能力属于节点启动代次，数据库在代次变更时强制清零，旧二进制不能继承上一代的新能力。服务和 Go 的完整能力校验还须在启用试点时完成。
- Go 提供稳定 `call_id` 和已校验身份。Python 的内部登记上下文为 `call_id`、`user_id`、`conversation_id`、`message_id`、`binding_id`、`binding_generation`、`binding_scope_revision`、`source_agent_id`、`source_row_id`、`authorization_versions`、`max_text_chars`。新调用的 max_text_chars 由 Go 在消息事务内固定，Python 首次登记后保留原预算；旧调用重试只改变该预算字段时复用原回执，其余身份变化仍拒绝。正文不进入任务载荷。内部适配器通过认证的 Go 元数据/上下文接口取得身份和正文，不允许从外部用户请求直接构造它。
- `group_expert_calls` 保存规范请求与摘要、固定快照及登记回执；`execution_runs.operation=group_expert`、`request_key=call_id`，占用键为 `group-expert:<call_id>`。群任务与个人任务共用 `_enqueue` 的全局和每用户队列计数，但不创建 `threads`、个人检查点或个人聊天记录。不得通过普通 `submit(operation=...)` 绕过专用登记仓储。
- 明确拒绝也保存登记回执，不创建执行任务。同 ID 同身份返回原登记结果；max_text_chars 只采用首次登记的预算，其余身份变化冲突；重新授权、容量恢复和快照变化都不能重写原回执。业务权限检查失败与尚未明确的网络故障必须区分，后者不得伪造拒绝。
- `group_expert_controls` 保存单调控制序号、派发序号和不可逆取消标记；每个 `(call_id, control_seq)` 的原始控制请求保存在独立回执表。取消先于登记到达时保留墓碑。迟到派发无权清除取消，重复控制返回当前已持久状态。取消响应中的 `saved` 只表示指令已保存，`stopped` 才表示已核清停止；`unknown` 不返回停止确认。
- 领取 SQL 在排序及分页前过滤未获派发许可的群任务，避免前 32 条等待群任务阻塞其他可运行任务。随后检查调用人与来源身份、授权修订及独立占用键。个人 `_thread` 检查保持原样；个人执行状态、事件重放及按请求查询不返回群任务，内部取消和结算可以为已撤权任务收尾。

### 快照、授权和结果

来源执行定义先由受控发布取得，再投影为只含批准角色正文、固定模型、生成参数、提供商代次/执行修订及模型预算的快照。允许读取的角色文件固定为 `AGENTS.md`、`SOUL.md`、`IDENTITY.md`；不复制 `USER.md`、`MEMORY.md`、`TOOLS.md`、技能、附件或工作区。工具列表取来源专家自身的已发布开关，当前支持搜索、图片生成和视频生成；每次调用创建独立目录，最多 4 次工具和 6 轮模型请求。来源名称头像另存展示资料，不进入执行摘要。

`AUTO` 仅在首次发布或明确重新发布执行定义时解析企业全局选中的模型；缺少有效全局模型时拒绝，显式无效模型不回退。展示资料更新复用既有执行快照，不重新解析 `AUTO`。提供商名称可重复使用，记录代次不可复用。其执行配置和凭据变化通过数据库触发器，在变更事务中递增修订并保存不含凭据的失效待办，配置改回原值也不能恢复旧版本。触发器产生的失效待办使用唯一的域/修订元组作为内部请求指纹；HTTP 投递时仍按规范载荷生成协议摘要。

调用至少依赖 `scope:<conversation_id>`、`user:<user_id>`、`source:<source_agent_id>:<source_row_id>`、`provider:<provider_generation>` 四个授权域，可增加部门等依赖。修订不存在或不匹配时拒绝，不能由客户端指定新修订后自动重跑。源发布时复核已提交的来源 manifest 和提供商修订；提供商凭据不进入调用快照、Go 镜像、结果或错误。

群范围的 `sources_json` 保存 `[{"source_agent_id":"...","source_row_id":123}]`，来源 ID 与记录代次同时匹配才可使用。准入及领取还检查当前范围修订、部门群所属部门范围、调用人的部门范围与调岗待确认状态。部门范围沿用已有个人授权规则：尚未配置部门资源池时保留既有分配，明确保存的空范围则撤销全部专家。组织成员信息由服务层在事务外向 Go 核对并同步，不能由调用人提交部门字段替代。

来源停用/更换、来源管理员失效、部门及群范围收回还在同一事务保存 `group_expert_binding_revocations` 和独立绑定失效待办；水位为群/来源记录代次的 `before_revision`。已登记的绑定范围修订低于水位时立即拒绝，即使其他授权已重新放开也不复活旧绑定。Go 必须应用过时通知中的独立失效水位，新绑定使用当前范围修订。

执行结果按共享协议保留事实。`completed` 时必须在同一事务保存唯一非空答复、结果摘要、执行终态和结果投递待办；超长/不完整答复由执行器先整理，包含提示后的字符数不超过登记的 `max_text_chars`。失败、取消和 `unknown` 同样保存可核对的持久交付结论。`unknown` 后的核对可以改变执行结算事实，不重新生成群答复。取消中保留执行占用；unknown 的记录、会话占用和未结算凭据不随群位置释放。群专家 unknown 的全局运行/模型准入临时占位最多 30 秒，预留模型消耗按上限暂计调用人额度；该用户在最近一次 unknown 后 30 秒内不能再登记或开始新的群模型轮次，已经受理的调用保留排队，窗口到期后可正常领取。此边界只限制全局准入占位，不是停止证明，不释放归属、不自动重放；实际消耗仍须按模型/工具证据核对。供应商明确拒绝和建立连接前失败可在同一终态事务按 0 结算；超时、取消、5xx 或缺少使用量继续记 unknown。

内部状态查询不包含快照或答案正文。生成完成后先按执行 ID 和原结果摘要通知 Go 进入 `awaiting_delivery`，不携带答案。结果投递和拉取补投必须先重新检查 Python 授权及 Go 的受限上下文，不能直接公开读取 `result_json`。Go 返回的交付回执绑定 `call_id` 和 `result_digest`，Python 在同一事务确认待办并保存 `confirmed` 或 `unpublished`；确认重试只接受同一份回执。补偿扫描按待办确认状态筛选，不以调用是否终态筛选；单次后台任务重试耗尽后仍按原操作 ID 退避重试，不删除业务待办。

### 内部接口约定

以下 v1 路由均已注册。主 Worker 默认拉取 Go 的持久待办；保留反向内部入口供核对/补投，二者调用相同登记和投递流程。认证凭据必须与普通用户令牌区分，绑定服务身份、用途、方法、路径、请求摘要及短有效期，不允许外部 `/api/im` 代理转发任意内部路径。

| Python 路由 | 请求与返回 |
| --- | --- |
| `GET /internal/group-experts/v1/capabilities` | 返回协议、部署模式、迁移版本、全部 Worker 校验结论；不能仅检查当前进程。 |
| `POST /internal/group-experts/v1/calls/{call_id}/register` | 按 `call_id` 登记；返回持久登记状态、原因码和 `run_id`。 |
| `GET /internal/group-experts/v1/calls/{call_id}` | 内部元数据查询，不返回正文；拒绝和取消墓碑也可查询。 |
| `POST /internal/group-experts/v1/calls/{call_id}/control` | `control_seq`、`kind=dispatch|cancel`，返回 `saved`、`execution_state`、`stopped`。 |
| `POST /internal/group-experts/v1/calls/{call_id}/delivery` | Go 请求补投；复用主动投递的授权流程，将原持久结果投递到 Go，不在查询响应中直接返回答案。 |

对应 Go 路由及回帖回执见[通信协议](../../services/communication/api/contract.md#group-expert-protocol-v1-schema-19)。无论网络是否超时，接收端都先依稳定业务 ID 和规范载荷去重；更换传输凭据不能更换业务 ID。

群工具从来源专家自身的已发布开关取得，不查询发起人的个人能力授权。来源工具配置修订由 `group_expert_tool_versions` 记录，修改或恢复配置均推进修订，旧执行无法恢复。工具调用先写入 `execution_tools` 的 `sent` 状态，获得明确结果后记为 `completed`；异常或失联保留 `unknown`，不得自动重放。每轮模型调用分别预留并结算，在继续工具执行前保存用量；后续调用失败不丢失已发生消耗。生成附件经 Go 持久上传后在唯一结果中保存 ID，不向模型或员工暴露服务端路径和凭据。
