# 公司群邀请专家计划

适用于 Octop Enterprise 同事聊天中的公司群、部门群和项目群。首版仅在 PostgreSQL 的 `web/worker` 分角色部署中启用，单体模式保持关闭。建议先在少量部门群和项目群试点，再开放全员公司群。

Go 通信服务负责群成员、消息历史、群专家绑定、调用调度和实时同步。Python 控制面和执行服务负责企业专家授权、模型调用和用量。[群管理与历史协议](../../services/communication/api/contract.md#group-upgrade-schema-13)的人员群基础上已接入[群专家 v1 协议](../../services/communication/api/contract.md#group-expert-protocol-v1-schema-19)。本计划限定这一阶段中群专家的范围。现有群聊交互见[企业客户端文档](../enterprise-client.md#消息与成果转发)。

## 工具扩展（当前规则）

群专家使用**专家自身的工具设置**，不是提问员工的个人工具授权。管理员在“专家 → 工具”中开启或关闭搜索、图片生成和视频生成；来源发布时只保存这些开关与修订，不复制凭据。成员的专家、模型及群发言权限仍决定能否发起调用，模型用量仍计入发起人额度。

每次调用创建独立工作目录，最多执行 4 次工具、6 轮模型请求，最后只发送一条群回复。每轮模型用量立即持久结算，工具先登记再执行；未知结果不重放，不因进程重启重复生成。工具配置关闭再开启也不会恢复旧调用。搜索使用专家允许的搜索服务；图片和视频使用企业配置的生成服务，服务凭据留在服务端。个人工作区、记忆、连接器、终端、输入附件和历史回溯不在工具扩展范围。

生成成果通过内部认证上传，在群回复提交时与消息原子关联；提交前任何群成员均不可读取，提交后沿用成员可见区间、清空和撤回规则。最多 4 个附件，图片受通信图片限制，视频受 50 MiB 文件限制。正文中的路径不会变成任意文件读取入口。

公司架构增加统一“管理群聊”入口，覆盖公司群、部门群和项目群。部门群候选为空时提示先配置部门可用专家。内部能力协议为 2，Python schema 36、Go schema 21；服务路由继续保留 `/internal/group-experts/v1`。已有群开关和专家绑定在部署时保留，由管理员自行管理。

## 使用方式和权限

| 事项 | 首版规则 |
| --- | --- |
| 邀请和移除 | 企业管理员、当前群主和该群管理员可管理群专家。群主和群管理员通过群详情操作，企业管理员从公司架构的群管理入口操作。普通成员邀请同事的权限只适用于人员。 |
| 群可用专家 | 企业管理员在公司架构的群管理入口为每个群维护“群可用专家”，候选为[专家资源来源](../expert-assignments.md#设置顺序)中已启用的普通专家；部门群还须在该部门的可用专家范围内。群主和群管理员只能从这个范围中邀请；企业管理员邀请范围外的专家时，同时把它加入范围。范围由 Python 按群会话 ID 和专家来源 ID 保存，并维护单调递增的范围修订号。绑定同时记录稳定的来源 ID 和来源记录代次，删除后重建同名或同 ID 专家不接续旧授权。 |
| 范围收回 | 来源停用或更换、部门范围收紧、群可用专家被移除时，Python 持久保存新范围修订及待同步操作，通过内部接口请求 Go 使相关绑定失效，失败时持久重试。同步未完成时管理界面显示“同步中”，Python 已按新范围拒绝新的执行和结果投递。已经发往 Go 的结果按下文的撤权生效边界处理。绑定失效后释放专家名额，群内显示系统提示，相关调用按状态表取消及释放调度位置。 |
| 数量 | **每群最多 3 位专家**。同一来源在同一群内只有一个有效绑定。群详情显示专家名称、头像和已用名额。新增、移除和名额检查在群会话锁下完成，支持并发操作和请求重试。 |
| 谁能调用 | 发起人须为当前有效群成员，满足消息权限、禁言及群状态规则，并按其个人使用该专家时的同一规则获得授权；开启“仅使用分配的专家”时须已获配该专家。员工只能从本部门范围获配专家，跨部门项目群中其他部门的成员可能无法调用，群详情需说明。管理权限用于维护群设置，读消息和发起调用仍按成员权限校验。 |
| 模型与用量 | 使用本次已校验快照中来源专家配置的模型。发起人未获该模型授权时本次调用不受理，不回退到发起人的其他可用模型，同一配置修订对不同发起人使用同一模型。模型用量计入发起人额度，已发生的调用消耗不会因取消或未回帖而退回。 |
| 如何调用 | 从群输入框的 `@` 菜单选中专家，提交对应的群内绑定 ID。菜单只列出发起人当前可调用的专家，由 Python 结合 Go 的有效绑定和本人授权返回；该列表只用于展示，执行前仍以 Python 判定为准。**每条消息最多调用一位专家，`@` 谁就由谁回答。** 同一条消息仍可提及同事。普通文字、`@全体`、转发消息和专家答复均按常规群消息处理。 |
| 回答与追问 | 专家以自身名称和头像发送一条文本答复，引用触发它的原问题，按群消息权限展示。追问时引用上一条答复并再次 `@` 专家；专家只读到这条答复和新问题，看不到更早的提问，界面需提示专家不保留之前的对话。每群保留 1 个执行调度位置、最多排队 3 个，由 Go 控制派发。正常执行和已派发后的取消中占用该调度位置，结果未知的特殊处理见状态表。所有已受理的等待任务统一计入共享队列的个人及总排队上限。专家调用未受理时保留已通过普通消息校验的群消息，在原问题旁显示原因。 |

邀请时，Python 校验所选专家在该群的可用范围内，Go 在写入绑定时校验群状态。群详情入口还须校验操作者的当前群主或群管理员角色。Go 现有组织路由只检查 `departments` 权限，不识别企业管理员角色，因此公司架构入口由 Python 校验企业管理员角色及 `departments` 权限，通过认证的内部接口提交带操作者身份的管理请求。此路径允许企业管理员不是群成员，不套用群主角色检查，也不授予历史读取或发起调用权限；外部请求不能自行声明管理员代办身份。新增管理接口按协议携带 `request_id`，操作回执使用新的 `group.expert` 范围。调用时，Go 核对成员身份、发言权限、绑定状态和本群排队数；Python 在执行前核对群可用范围、发起人的专家与模型授权以及额度，不在 Go 发送事务中同步调用 Python。邀请、移除、发起和回帖记录对应的操作者或任务 ID。相关规则见[企业专家分配](../expert-assignments.md)及[模型授权实现](../../src/octop/infra/users/model_access.py)。

### 管理请求的修订与绑定代次

Python 在同一事务保存范围修订 `scope_revision` 和待同步操作，来源、部门或群范围变化都使受影响群的修订递增。邀请携带预期范围修订、来源 ID 及来源记录代次，Go 在群会话锁下对照已应用的范围修订校验后写入绑定。修订落后的邀请拒绝，修订超前时先在事务外同步权威范围，再重新校验。相同修订对应的范围内容必须一致，相同 `request_id` 的重试复用原回执，修改载荷须使用新请求。

Go 保留已应用范围修订的高水位。旧范围同步不得覆盖新范围，已经应用收回操作后，迟到的旧邀请不能恢复授权。移除操作携带明确的绑定 ID 和代次，迟到重试只能处理该次绑定，不能按来源 ID 删除后来重新邀请的绑定。范围重新放开只恢复候选资格，重新入群须发起新的邀请。Python 只有收到 Go 的持久回执后才把管理操作标记为同步完成，未确认期间继续按当前权威范围拒绝失效调用。

来源或范围撤回在权威变更事务内另存每个群及来源记录代次的绑定失效水位 `before_revision`，并保存独立失效待办。即使撤回后立即重新授权、较新的范围先到达 Go，旧绑定仍须失效；过时通知不能删除范围修订已达到水位的新绑定。Python 准入、调用和投递还按登记身份中的 `binding_scope_revision` 校验水位，不等待 Go 同步后才拒绝旧绑定。

授权失效确认和绑定移除完成使用各自的回执。后者必须包含绑定状态、专家名额和群系统提示的提交，不能仅凭授权镜像已更新就宣称专家已移出群。

### 授权失效与最终回帖的生效边界

群范围、个人专家授权、个人模型授权、来源执行配置及模型提供商执行配置都纳入持久授权修订，不能只在 Python 发出回帖前检查一次。Python 为相关授权域维护单调修订，Go 保存对应的修订镜像及失效操作回执。镜像只包含身份、修订和必要的模型标识，不下发模型凭据或专家定义正文。提供商以不可复用的记录代次区分同名删除重建；修改服务地址、协议、请求参数、凭据或所选模型能力时，在提供商变更事务内保存新执行修订和失效待办。仅展示资料或备注变化不推进执行修订；提供商的 `name` 同时参与模型引用，改名属于执行配置变化。

1. Go 创建调用时记录该调用所依赖的授权域修订 `authorization_versions`，Python 登记时与当前权威修订及实际授权逐项核对，固定到调用快照。明确发现镜像尚未初始化或修订不一致时，本次调用按 `rejected` 不受理，提示权限配置正在同步，合法群消息保留，不能自动替换修订重跑。仅请求超时、尚不知道登记结果时保持待确认。修订由服务端取得，客户端不能指定或覆盖。执行前及结果投递前继续核对，旧调用不能因后来重新授权而恢复。
2. Python 保存撤权、部门范围收紧或新执行配置修订时，在同一事务登记带稳定操作 ID 的失效通知。来源配置通过现有受控快照发布机制提交执行修订，不能只靠进程内回调通知。Python 提交后立即拒绝失效修订的新执行和新投递，随后异步通知 Go；管理端暂显示“同步中”。仅名称头像变化不推进执行授权修订。
3. Go 在短事务中更新相应授权域修订，并持久登记受影响调用的失效及取消待办，提交后返回回执。回帖事务先按固定顺序对依赖的授权域行加与修订更新互斥的读锁（PostgreSQL 使用 `FOR SHARE`），再取得群会话锁并检查调用修订，最后锁定调用和输入消息。失效更新持有相同授权域行的写锁。两者以数据库提交顺序裁定先后，所有新增路径遵循“授权域按键排序、群会话按 ID 排序、调用、输入消息”的锁顺序，不在锁内向另一服务查询。
4. 只有收到 Go 的持久失效回执，管理端才显示“群调用撤权已生效”。回帖若先提交，则属于生效前已发表的消息，保持历史记录；失效若先提交，旧版本结果必须被拒绝，包括已经离开 Python、正在网络中或等待 Go 群锁的回帖。“同步中”期间不能承诺已发出结果全部被拦截。撤权生效也不等于上游模型已经停止，停止与用量核对独立进行。
5. 未处理完的失效待办继续按绑定代次和旧授权修订取消受影响调用，包含 Go 尚待 Python 登记确认的调用。范围或权限重新放开不会复活这些旧调用。乱序同步可以跳过过时的范围内容，但不能丢弃其中尚未完成的旧绑定失效、取消和确认工作。直接在 Go 发生的退群、禁言、绑定移除、归档和解散，在其本地事务中禁止相关回帖并登记取消待办，沿用同一状态和补偿规则。

## 专家可读的消息范围

1. 每次调用只向模型提供**当前 `@` 消息的正文，以及发起人明确引用的一条消息正文**。以本次消息携带的 `reply_to_message_id` 为准，只取直接引用。每次根据这两项和管理员批准的角色定义重新构建单轮输入，允许在当前调用内使用上述受控工具。历史、输入附件、知识库、个人记忆和个人工作区均在调用范围之外。
2. 发送事务首先沿用普通群消息及引用校验。引用不存在、跨群、发起人无权查看或按其当时的 `cleared_through_seq` 已清空时，拒绝整条消息，不落库、不创建专家调用，也不静默丢弃引用。通过普通消息校验后，Go 按消息 ID 从通信库取正文，另行核验两条消息都处于该专家本次绑定生效之后、正文有效且未撤回，引用须早于当前消息。专家移除再邀请时生成新绑定和新的起始序号。
3. 当前 `@` 消息由发起人自己发到群里，只按发起人的权限校验。被引用的消息还须对**所有能看到专家答复的群成员**可见。Go 按群消息的可见性规则确定答复受众，对每人核对成员可见区间 `member_epochs`。清空标记只在提交引用时检查发起人当时的可见性，不参与答复受众判断。提交后的清空仅影响个人历史显示，无论发起人还是其他成员清空，都不取消调用。执行前及回帖前仍复核成员可见区间、正文和撤回状态，不再用清空标记否定已合法提交的输入。后续消息和状态展示仍遵守各读者自己的清空标记。
4. 普通消息合法，但专家加入时间、引用受众、专家授权、文本调用条件或排队限制不满足时，保留群消息，仅将本次专家调用记为不受理并显示原因。调用模型前重取并校验消息，写入答复前再次核对群状态、发起人的发言权限、绑定、输入消息和被引用消息的受众。任一校验失败时结束本次调用，在原问题旁显示原因。消息撤回、发起人失去调用权限或被禁言、专家移除、群归档或解散时，取消相关排队任务并拦截在途任务的迟到回复。

例如，张三引用周一的排期消息请专家提炼待办，李四在周二入群后只能读周二起的消息。即使张三能读周一的排期，本次调用也不能把那条排期变成李四可见的群答复，发送时即提示不受理。若李四在任务执行中加入，由回帖前校验拦截。不带引用、只 `@` 专家提问时，执行中有人入群不影响回帖。公司群持续有新员工加入，引用较早的消息常会不满足条件，这也是先在部门群和项目群试点的原因之一。相关实现见[消息发送与引用检查](../../services/communication/internal/chat/chat.go)和[引用预览的可见性检查](../../services/communication/internal/chat/message_view.go)。

### 文本输入与输出边界

- 客户端和服务端均检查是否有实际问题。仅有点名标签和空白，或仅有附件而没有问题正文时，专家调用不受理。带附件的合法问题可以调用，但只读取正文，界面提示“专家不读取问题附件，可生成群消息附件”。被引用消息只有图片或文件、没有有效正文时，本次调用不受理，不自动忽略引用。正文中的链接不自动抓取，引用链不递归展开。
- 普通消息超出通信服务现有长度限制时，整条发送失败。问题、引用及角色提示合计超出所选模型的上下文预算时，专家调用不受理并提示缩短内容，不静默截断输入。实际模型请求显式设置输出 token 上限，沿用现有模型调用配置及默认值，并限制在模型能力和剩余上下文预算内。
- 最终答复连同提示文字最多使用通信服务的 `MaxTextChars` 个字符，按现有服务端字符计数口径校验。超长时截取可容纳的正文并附“答复已截断，请缩小问题后重新提问”，保留截断状态，仍只发送一条消息。模型达到输出 token 上限时也标记答复未完整生成。没有有效文本结果时显示调用失败，不发送空消息，不自动再调用模型补全。整理后的唯一答复先持久化，再进行回帖重试。

## 专家团可复用的功能

现有[专家团队](../expert-teams.md#说话与调度)以主持人的会话作为房间。用户点名后，主持人把 `@` 当作派工优先提示，改写任务后交给成员，成员用自己的头像和名字发言。其成员派工会从主持人的会话取最近最多 40 条记录来整理背景，在途队列和编制锁保存在进程内。

| 环节 | 复用方式 |
| --- | --- |
| 专家选择 | 复用 [TeamMemberPicker](../../dashboard/src/pages/Experts/components/TeamMemberPicker.tsx) 的搜索、头像和去重展示。该组件保存时整组替换，并只允许选择本人自有或共享的专家；群专家改为逐个邀请和移除，每次携带 `request_id`，候选来自服务端返回的群可用专家，名额由 Go 权威校验。 |
| 点名与署名 | 扩展[同事聊天的结构化提及](../../dashboard/src/pages/Messaging/colleagueMentions.ts)，区分成员 ID 与专家绑定 ID。复用[专家头像组件](../../dashboard/src/pages/Chat/components/MessageSender.tsx)及专家团按说话人渲染气泡的方式。 |
| 单轮执行 | 参考[专家团的单轮请求](../../src/octop/infra/agents/teams/team_manager.py)组织输入，但不在任何人的专家运行时中派生会话。群调用基于来源专家当前已校验的运行快照，加载管理员维护的定义、角色提示和工具开关，创建本次群调用的独立目录，不加载 USER.md、MEMORY.md、个人技能和凭据；只向模型声明来源专家已启用且群执行器支持的工具。不使用发起人的私有实例，也不使用来源管理员本人的专家。调用按群、绑定和调用 ID 隔离。 |
| 结果回群 | 复用专家团给结果标记发言者、显示独立气泡的做法。群绑定、持久任务、授权和最终消息使用企业通信和共享执行链路。主持人自动派工和收尾适合未来的 `@专家团` 场景。 |

### 专家配置快照与历史署名

Python 登记调用时校验并固定来源 ID、来源记录代次（沿用现有 `source_row_id` 语义）、执行配置修订、角色提示、模型及生成参数，记录快照摘要。同一个 `call_id` 的重试使用同一快照，不能在重试中换成另一版本或另一模型。快照只保存批准的执行定义，不混入个人资料、技能、凭据或工作区内容。

发布群专家执行定义时，先把模型解析成唯一的 `provider/model`。显式配置的模型不可用时拒绝发布；`AUTO` 或未配置模型时，只使用发布时企业全局选中的有效模型，未设置或不可用时提示管理员先指定模型，不能从发起人的授权列表或任意首个可用模型中选取。解析结果与来源定义一起持久发布；修改全局模型不会悄悄替换已发布的群专家模型，重新发布后才产生新执行修订。

快照同时固定提供商记录代次、执行修订以及所选模型的上下文、输入和输出上限，保存不含凭据的配置摘要。调用前核对当前提供商身份及修订，凭据只在模型请求前按该身份和修订从服务端读取，不写入调用快照或 Go 镜像。提供商变更或同名删除重建时，旧任务按配置失效取消，不自动改投新地址、新模型或新凭据。配置改回原值也不得恢复旧调用。

执行前和提交答复前核对当前授权及执行配置修订。来源定义、角色提示、模型或生成参数变化时，按授权失效流程取消旧快照对应的排队及在途调用，拦截尚未提交的旧结果，提示“专家配置已更新，请重新提问”。Python 已完成生成但 Go 尚未回帖时，只取消群回帖，保留 Python 已完成的执行记录及实际用量。已经发出的模型请求按实际结果结算，不自动换新配置重跑。仅名称、头像等展示资料变化不取消调用，执行修订与展示资料分别记录。

绑定移除采用失效标记并保留代次、最后的名称头像及历史消息关联。有效绑定的展示资料按当前群资料更新，失效后保留最后一份署名快照及所需头像资源引用，来源删除后历史答复仍能正确署名。重新邀请生成新绑定，历史消息不能被改指向新绑定。

## 服务端接入与重试

### 状态权威与对应关系

Go 的 `call_state` 管理群内受理、派发和回帖，Python 的 `execution_state` 管理模型执行、共享占用和用量。两者通过 `call_id` 关联，Python 的 `completed` 只表示生成已完成，Go 的 `completed` 才表示答复已提交到群。任何一侧不得直接用自己的终态覆盖另一侧的执行事实。

| 场景 | Go `call_state` | Python `execution_state` | 群位置与共享资源 |
| --- | --- | --- | --- |
| 消息合法，等待登记确认 | `pending_admission` | 无执行记录，或已 `queued` 但回执未到 | 占一个群预留位置。Python 已登记时即计入共享排队，确认丢失不重复登记。 |
| 专家条件或共享准入明确拒绝 | `rejected` | 无执行记录，保存拒绝回执 | 释放群预留位置，不占执行和模型资源，不自动重试为新调用。 |
| 已登记，尚未取得本群派发许可 | `queued` | `queued` | 占群等待位置并计入个人和总排队上限，不占运行及模型名额。 |
| 已取得本群派发许可 | `dispatched` | `queued` 或 `running` | 占唯一群调度位置。等待共享准入时仍计排队，实际领取后按协议占运行、模型及额度资源。 |
| 答案已生成，尚未写入群 | `awaiting_delivery` | `completed` | 继续占群调度位置，模型资源及额度按执行协议完成结算。只重试投递，不再生成。 |
| 答复和完成回执已在 Go 提交 | `completed` | `completed` | 释放群调度位置并推进队列。重复投递只返回原回执。 |
| 明确执行失败，或已完成的结果永久无法发表 | `failed` | `failed` 或结果已完成的 `completed` | 释放群位置；Go 保存失败交付回执，Python 已完成的执行与实际用量不改写。 |
| 已发出派发许可，正在取消 | `cancel_requested` | `queued`、`running` 或 `cancel_requested`，等待确认 | 立即禁止回帖，继续占群调度位置，暂不派发下一个。收到已停止或已完成的持久状态后转 `cancelled`，确认为 `unknown` 则走结果未知规则；2 分钟未取得可核对结论时，Go 仅终止群回帖资格为 unknown，取消待办继续补偿。 |
| 从未派发的调用被取消，或已确认执行结束但禁止回帖 | `cancelled` | 无记录、待取消的 `queued`、已 `cancelled`、已结束的 `failed` 或 `completed` | 释放群位置。尚未收到 Python 取消回执时，共享排队仍由 Python 计数，未确认通知继续补偿。Python 已 `completed` 的记录和用量不改写。 |
| 上游结果或执行状态无法核清 | `unknown` | 已 `unknown`，或仍等待取消核对 | 终止群回帖资格并释放群位置；Python 实际状态、模型/工具审计及未确认用量保留，群专家 unknown 的全局准入占位最多 30 秒，发起人的新群调用最多暂停 30 秒，已经受理的调用继续排队等待。 |

正常路径为 `pending_admission → queued → dispatched → awaiting_delivery → completed`，空闲群可在确认登记后直接从 `pending_admission` 进入 `dispatched`。结果到达后能在同一事务回帖时，也可从 `dispatched` 直接完成。表中 Python 状态为已核对值，通知延迟允许 Go 暂时滞后，但推进状态必须依据持久记录。终止路径使用 `rejected`、`failed`、`cancelled` 或 `unknown`，Go 的这些状态和 `completed` 均不能被迟到通知改回可执行或可回帖状态。状态通知带单调控制或结果序号，重试不降级本地已确认状态。Python 的 `unknown` 后续可按共享协议核对为终态，Go 的 `unknown` 仍保持不可回帖。

取消前是否派发，以 Go 持久派发许可为准，不能依据尚未更新的 Python 状态猜测。未派发调用可立即在 Go 终止并释放等待位置，已派发调用必须按表等待执行确认。已经生成的答案被撤权拦截时，Go 记 `cancelled`，Python 保留 `completed`，并记录“结果未发表”的交付结论。每群 1 个调度位置是准入规则，`unknown` 后释放位置不构成旧上游请求已经停止的保证。

`rejected` 仅用于登记为执行任务之前的明确不受理。已受理任务后来发现输入超限、无有效输出等确定失败，按执行事实进入 `failed`；权限或上下文失效走取消分支。客户端沿用具体原因提示，不能为了统一显示“未受理”而把已有执行任务改成不存在。

### 消息入库、共享准入与群内派发

Go 维护群专家绑定（加入序号、代次、状态和邀请人）及每次调用记录。发送接口增加可选的 `mention_expert_id`，其值为该群的专家绑定 ID，`messages` 增加对应字段。沿用 `client_message_id`，将专家绑定纳入请求摘要，并以原消息 ID 与绑定 ID 作为调用的幂等键，生成稳定的 `call_id`。普通消息校验失败时整条拒绝。专家本地条件满足且取得预留位置时，合法消息、调用记录及登记任务在同一事务写入；仅专家条件失败时保存合法消息及拒绝原因，不创建执行登记任务。任务载荷只保存消息、绑定和调用标识，正文按权限即时读取。复用 [`background_jobs`](../../services/communication/migrations/0006_jobs_push.sql) 及现有 [`store.EnqueueJob`](../../services/communication/internal/store/store.go) 在调用方事务内入队；不能使用直接通过连接池写入的 `Supervisor.Enqueue` 承担该原子性。

Go 在群会话锁下预留 1 个派发位置及最多 3 个等待位置。待 Python 确认的调用也占本群位置，显示“待确认”，不能标为已受理。所有预留位置的调用都立即异步向 Python 登记，包括尚未轮到本群派发的 3 个调用，不等轮到它们时才登记。Python 先完成所需的 Go 权威读取，再在短准入事务内复核本地授权修订、个人及总排队上限并持久保存任务。超限或无权调用时明确拒绝，Go 保存拒绝结果、释放本群位置，保留合法群消息。两侧均不在数据库事务内等待网络请求。

Python 的群任务使用独立调用记录，不占用个人会话。共享执行新增 `operation=group_expert`，使用 `request_key=call_id`，执行占用键按 `group-expert:<call_id>` 隔离，不创建可见的个人聊天线程。群调用记录保存调用人、群、绑定代次、来源身份、快照和授权修订，适配现有提交、领取、检查、取消及核对中的个人线程归属检查，原个人任务校验保持原样。内部取消、回执和结算允许已撤权任务继续收尾，但不恢复生成或正文读取权限。所有已受理但未运行的群任务都计入共享 `queued` 数量，以尚未获群派发许可的状态等待。领取逻辑必须同时检查群派发许可，不能被普通 Worker 提前领取。Go 按原消息序号安排本群顺序，较早的待确认调用未核清前不跳过它派发后续调用。

Go 在群会话锁下为队首已受理调用持久保存派发许可及控制序号，再通过短后台任务通知 Python。Python 依据 `call_id` 和控制序号幂等处理，取消后的迟到派发不得恢复任务。执行前重新向 Go 核对该调用仍持有本群许可并通过消息权限检查。每次群调用结束时，在同一 Go 事务更新状态、释放位置，并为下一个已受理的队首记录派发操作。队首仍待确认时，保留位置等待登记确认后再派发。运行时才按共享协议取得全局执行和模型并发名额，并在模型请求前预留额度，群派发许可不保证模型立即开跑。

### 跨服务确认、重试与状态核对

- **登记幂等。** Python 对群任务以 `call_id` 建立唯一约束，绑定发起人、群、原消息、绑定代次和请求摘要，重复请求返回同一任务，载荷不同则冲突。同一调用只取得一次配置快照。明确拒绝也持久保存请求摘要和拒绝回执，不能在容量恢复或重新授权后把同一拒绝请求变成新执行。Go 未收到登记响应时，查询或重投同一个 `call_id`，不创建新的执行任务。已知模型请求尚未发起时可继续原任务，结果未知时不自动重试模型。
- **结果持久化。** Python 在同一事务保存执行终态、固定后的答复或失败原因、结果摘要及待回帖记录，之后再投递给 Go。后台任务只做登记、控制通知、状态查询或结果投递，不持续占用 Go 后台任务等待模型生成。已完成的结果重复投递只能补交同一份内容，不能重新调用模型或重新整理出不同答复。
- **回帖确认。** Go 将回帖、调用完成状态、同步事件及队列推进放在同一事务，提交后返回持久回执。相同调用和结果摘要重投时返回原回执，内容冲突则拒绝。结果因撤权等原因永久不能回帖时，也保存终止状态和原因回执，Python 收到后停止投递。已完成回帖的确认重试只返回原回执，不重新执行权限校验来改变已提交结果。
- **定期核对。** Go 周期扫描非终态调用并核对本地权限，主 Worker 拉取 Go 的持久登记/控制待办，并从 Python 的独立结果待办补交终态或回帖。生成完成后先按执行 ID 和原结果摘要通知 Go 进入 `awaiting_delivery`，不携带答案。另有独立扫描处理所有未确认的范围同步、授权失效、登记、派发、取消、结果投递和回执待办，不按群调用是否终止筛掉记录。Python 同样扫描未确认的控制回执、失效通知和结果投递，Go 已 `cancelled` 或 `unknown` 仍须继续核对必要的取消及结算确认。单次 HTTP 超时只能说明状态待确认，不能据此认定模型未执行、创建新调用或释放共享占用。
- **取消顺序。** Go 的取消状态和待取消通知一起持久化，Python 持久处理取消指令。取消先于登记到达时也保留 `call_id` 的取消记录，阻止迟到登记重新创建可执行任务。取消回执区分“指令已保存”和“执行已结束”，收到前者不能释放运行资源或已派发的群调度位置。Python 已 `completed` 或 `failed` 时返回原终态及未发表结论，不改写执行终态。已 `unknown` 时返回该持久状态供 Go 进入结果未知分支，不伪造停止确认，资源继续核对。任何迟到控制通知或结果都不能把已终止调用变回可执行、可回帖状态。

补偿待办具有稳定操作 ID、请求摘要、目标及确认状态，与产生它的业务变更同事务保存。`background_jobs` 的单次任务成功、超时或重试耗尽，只代表这次投递尝试的状态，不等于对端已处理。达到重试上限后保留待办，由周期核对按退避策略重新安排投递并记录异常，不能删除待办或换新业务 ID。已确认的业务终态与仍待确认的通知分别展示和统计。未完成补偿、未知用量或关联回执未核清时，不清理调用、绑定墓碑和去重依据。

### 执行授权、结果未知与回帖校验

Python 在执行前及尚未回帖结果的每次投递前读取当前群可用范围、发起人的专家与模型授权及执行配置修订，撤权或配置变化时按状态表终止执行或群回帖。主动推送和 Go 拉取补投共用这些授权检查，状态查询不能绕过检查直接取答复。已经回帖的确认重试只核对 Go 原回执，不改写已提交状态。Go 回帖接口仅供认证的内部服务投递已持久化结果，核验 `call_id`、绑定代次、授权修订、执行记录和结果摘要，旧执行者的内存结果不能绕过持久记录直接回帖。

回帖事务按授权失效章节的顺序锁定授权域、群会话、调用及存在的输入消息，复核授权修订、回帖资格、群状态、发起人的发言权限、绑定和被引用消息的受众。成员变更和绑定移除须持有同一群会话锁，撤回更新消息行并与输入消息读锁互斥。提交后的清空仅影响个人显示，因此不增加清空与回帖之间的互斥锁。每次尚未入库的结果补投也遵守这些检查。

撤回接口沿用现有消息行锁，在原事务内追加按消息 ID 定位的取消待办，再由事务外的处理器按统一顺序锁群会话并更新调用。不能持有消息行锁后反向获取群会话锁。即使取消待办尚未处理，回帖检查也会因消息已撤回而拒绝写入。

模型请求结果未知时，Python 按[共享执行协议](execution-contract.md#身份与状态)记录 `unknown`；Go 将群调用记为结果未知，终止回帖资格并释放本群调度位置，不恢复迟到结果的回帖权。共享执行记录、模型与工具未知回执及会话占用继续留存；群专家 unknown 只对全局运行/模型准入保留 30 秒的临时占位，未确认模型消耗按预留上限暂计发起人额度，后续依据证据核对结算。发起人在最近一次 unknown 后 30 秒内的新登记被拒绝，已受理调用保留排队；到期后允许新登记、领取和模型预留，未确认用量继续计入额度。30 秒到期不构成上游已停止或用量已经核清的证明，不释放工作区归属、不允许重放旧操作。明确未发出的连接错误和供应商明确拒绝按 0 结算并失败；超时、取消、5xx 及缺少用量回执仍保留未知事实。

### 署名、同步与客户端兼容

答复以 `call_id` 作为 `client_message_id`，借助现有发送者幂等索引，每个调用最多写一条答复。`sender_id` 使用群专家绑定 ID，`messages` 增加发送者类型字段，区分成员和群专家。群资料、历史读取、引用预览和同步数据均携带可解析的专家署名，失效绑定按历史署名规则保留。新客户端按发送者类型显示专家，并把对有效专家消息的右键 `@` 改为点名该专家，失效绑定提示专家已移除。

客户端按状态表展示待确认、未受理、排队、等待执行或执行中、待回帖、已完成、失败、取消中、已取消及结果未知，不能把 Python 已完成直接显示为群内已回答。状态和权限失效提示只返回状态及原因码，读取仍须通过对应消息的可见性检查。旧客户端按 `sender_id` 在同事资料中查找发送者，找不到时显示默认头像和“同事”，应能正常阅读答复文本。现有旧端右键点名会先查询群成员，找不到专家绑定时在前端提示成员不可用，通常不会提交调用。若更早客户端提交了无效人员提及，服务端仍按原成员规则拒绝，不得误触发专家。兼容验收允许明确的不可用提示，要求页面不崩溃、普通阅读和发送可继续使用。桌面界面随内嵌网页资源打包，见[桌面资源说明](../../desktop/README.md)。

上线顺序为保持功能关闭、排空并停止旧执行者、完成两侧数据库迁移、启动协议匹配的新服务及全部 Worker、初始化授权镜像、核对协议能力、开启试点。按[分角色部署规则](../../docker/enterprise/ROLES.md)处理未结束任务和停止确认；协议能力按节点启动代次登记，默认不支持，缺席、失联或仅有过期心跳不视为旧执行者已停止。不能只让新 Worker 检查能力，而留下仍会读取同一队列的旧 Worker。完成全链路之前，新服务同样不宣告可启用能力。

暂停试点先关闭新的群专家受理，保留历史阅读、回帖确认和补偿入口，按需排空或取消已有调用。回退到不识别群任务的服务前，须核清全部群任务、未知资源占用及未确认通知，停止新执行者，并采用该版本支持的 schema 和数据快照。存在未核清任务时不得启动旧 Worker 接管。仅关闭功能开关不会撤销数据库迁移，也不会自动清除未结算用量。

### 可靠性边界

- Go 迁移 `0021_group_expert_reliability` 停止旧的逐调用循环任务，保留业务待办与历史，并固定新调用的文字上限、补充活跃调用/撤回待办索引与触发器状态过滤。已存在的 0017–0020 不折叠。
- 逐调用核对使用一次性 `group.expert.reconcile.call`，只有 `group.expert.reconcile` 自身周期执行。核对按调用 ID 游标分页，每调用独立短事务，无变化不改写 updated_at；单条失败记录日志并保留待处理状态，不使全局周期任务退避，单条一次性任务仍按自身错误重试。读接口不申请群会话排他锁，回帖和管理变更仍遵守授权域 → 群 → 调用 → 输入消息的锁顺序。
- 已受理登记的回执始终保持原 run_id 和空拒绝原因；执行失败、取消或 unknown 的原因保存在交付结论中，不改写重投时的受理结论。
- 待登记最多 5 分钟，排队/派发最多 1 小时，待回帖最多 10 分钟，超时先保存取消操作。已派发取消超过 2 分钟未核清时，Go 转 unknown 并推进群队列，继续保留跨服务取消待办；不替 Python 伪造停止或用量结论。无效文本、失效附件等确定的投递错误保存 failed/unpublished 回执并推进队列；附件仍在处理时按原结果重试。
- 邀请只等待本群范围、绑定、所选来源及其模型提供商的同步，不因无关群的待办阻塞。群主收到明确失败后刷新范围并生成新请求；网络/5xx 未知结果仍复用原 ID 与载荷。
- 主 Worker 的能力心跳独立每 3 秒运行；列表只读取 Go 的未过期能力证明，不续写心跳。发布与权限投影每 5 秒检查修订，版本表在数据库内汇总，来源身份变更复用单个 source head 的 dirty_revision，不把所有用户/agent 行传回 Python。只在清单、提供商、来源或权限数据变化时重建，bootstrap 只在服务实例首次投递前补齐。部署须保持 Python、Go 与 PostgreSQL 时钟同步，15 秒凭据和能力证明仍按协议到期。
- 消息列表在原查询中取得专家元数据；原提问显示被提及专家名。前端状态使用持久同步事件和断线历史补读，取消逐调用轮询；group.expert.call 按消息 ID 刷新已缓存提问，即使提问已超出最近 50 条。单条刷新与历史分页串行，刷新失败不推进同步游标。附件文件写入移至群事务之外，用文件摘要及元数据验证幂等，不再为摘要重新编码完整附件。

## 定向验收

- **邀请与调用权限。** 并发邀请时第 4 位专家被拒绝，同一 `request_id` 的重复邀请复用同一绑定，修改载荷则冲突。覆盖企业管理员、群主、群管理员、普通成员、非成员和仅有 `departments` 权限的非管理员，以及禁言、专家或模型未授权、群可用范围外、跨部门成员。公司管理员从群管理入口操作时，读取历史仍校验其成员权限。
- **范围与代次。** 覆盖来源、部门及群范围收回，核对绑定失效、名额释放和排队任务取消。模拟收回先于迟到邀请到达、范围同步乱序、移除回执丢失以及移除后重新邀请，旧邀请不能恢复授权，旧移除不能删除新绑定。来源删除重建不接续旧授权，同步未确认时展示待同步状态，执行按 Python 当前授权拒绝。
- **撤权生效与回帖竞争。** 分别对个人专家授权、模型授权和来源配置设置并发屏障，让结果通过 Python 检查后停在 Go 提交前。验证失效先提交时旧结果被拒绝，回帖先提交时保留原消息和用量，管理端只在 Go 失效回执后显示已生效。覆盖通知丢失、重新授权和乱序版本，旧调用不能恢复，新调用须使用当前修订。
- **消息范围与清空。** 用可控模型核对实际输入，覆盖当前消息及至多一条直接引用。跨群、引用不存在、本人无权查看和提交前已清空的引用拒绝整条消息。专家加入前消息、引用受众不满足等专家条件失败时，合法群消息保留而调用不受理。带引用的调用在排队或执行期间有人入群时回帖被拦截，不带引用时照常回帖。提交后发起人或其他成员清空不取消调用，撤回任一输入仍拦截回帖，清空后的历史与状态读取不越过个人标记。
- **任务确认与重试。** 覆盖重复发送、登记成功但响应丢失、Worker 重启、模型完成后回帖投递丢失、Go 已写答复但回执丢失，以及后台任务达到重试上限后周期核对恢复。核对同一 `call_id` 只对应一个模型执行，不重复计费且最多产生一条答复。同 ID 不同载荷或不同结果摘要被拒绝，取消先于登记或派发到达时不能复活任务。排队、执行及待回帖期间发生撤权、禁言、退群、归档或解散时，核对任务取消和迟到结果拦截，主动推送与拉取补投都不能绕过授权。
- **两侧状态及终态补偿。** 验证 Python `completed`、Go `awaiting_delivery` 时撤权，只终止群回帖，不改写已完成执行或退回实际用量。Go 已取消未派发调用后，令取消通知耗尽重试，再恢复服务，独立待办扫描仍能完成取消并释放 Python 排队占用。取消指令已保存但执行未停止时，不能伪造已停止确认；超过取消等待上限时 Go 只终止回帖资格为 unknown，Python 仍按其实际执行状态计数。失败和拒绝回执重投、已经发表后的确认重试、unknown 后用量核对均不使 Go 终态复活。
- **队列与结果未知。** 在共享容量充足时，每群第 2 至 4 个调用等待、第 5 个不受理，前一个结束后按顺序推进。待确认调用占群位置，所有已受理等待任务同时计入个人及总队列，跨多个群提交也不能绕过上限，缺少群派发许可时 Worker 不得提前执行。模型结果未知时迟到结果不回帖，审计、会话与未确认用量继续保留；核对群 unknown 在 30 秒后不再计全局运行/模型准入，发起人的新群调用只在这 30 秒内被拒绝，已经受理的调用不被连带取消，到期后恢复领取；其他用户和个人会话不被其长期占住全局名额。
- **配置与署名。** 排队、执行和结果重投期间修改来源定义、角色提示、模型或提供商执行配置，旧调用取消且不换新模型重跑，实际消耗仍结算。覆盖 `AUTO` 发布时固定企业全局模型、无有效全局模型时拒绝发布、提供商同名删除重建以及配置改回原值；快照、错误和 Go 镜像不得包含凭据。仅名称头像或提供商备注变化时更新展示而不取消。移除绑定、删除来源和重新邀请后，旧答复及引用预览仍使用正确历史署名，不能归到新绑定。
- **文本边界。** 覆盖仅有 `@`、纯附件、带附件的文字问题、无正文引用、正文链接、嵌套引用、普通消息超长及合并输入超出模型预算。附件和链接内容不进入输入，不补读引用链。验证模型请求具有输出 token 上限，超长或未完整生成的答复带提示且含提示后的总字符数不超过 `MaxTextChars`，空结果不发空消息、不自动补调模型，重投内容一致。
- **客户端。** 分别验证网页和企业桌面端的邀请、`@` 菜单过滤、回复署名、追问提示和各调用状态。旧端能以默认头像的“同事”普通文本阅读答复，右键点名提示不可用，页面不崩溃且普通发送仍可使用。模拟旧端直接提交专家绑定作为人员提及，服务端按原规则拒绝且不触发专家。
- **迁移与启停。** 验证 `group.expert` 回执约束、旧消息发送摘要兼容、群任务全生命周期归属检查及 API 可见性。单体模式、缺少拓扑节点、旧 Worker 未确认停止、协议不匹配或迁移未完成时启用被拒绝。关闭试点后普通聊天和已有结果补偿继续可用，存在未确认取消、unknown 或未结算占用时阻止旧 Worker 接管。
