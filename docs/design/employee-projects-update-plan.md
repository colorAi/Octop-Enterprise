# 员工客户端多项目与多专家更新计划

编写日期：2026-11-03。更新日期：2026-11-06。状态：源码实现及定向检查完成；Windows/macOS 安装包真机验收待执行。

目标：将员工客户端的单个全局工作目录，改为可长期保存和切换的本地项目；新对话默认使用当前项目，也可以选择其他文件夹；同一项目可以使用不同专家分别开展对话。

本文件保留实施计划，并在第 11 节记录实际交付和验证边界。源码版本按维护者要求保持 `1.0.1b3`，功能修改提交本地 Git。实施只运行修改模块及关联检查；前端和桌面内嵌资源已生成，安装包发行另按维护者安排执行，不推送远端。

## 1. 产品关系与使用流程

采用“项目 → 对话 → 专家”的主流程。专家仍是独立的能力资源，一个项目可以使用多个专家，一个专家也可以用于多个项目。

| 对象 | 负责的内容                                     | 本期规则                                     |
| ---- | ---------------------------------------------- | -------------------------------------------- |
| 项目 | 本地文件夹、项目名称、所属对话、最近使用的专家 | 保存后可重复打开；新项目直接使用选中的文件夹 |
| 对话 | 聊天记录、模型设置、审批设置、执行与恢复记录   | 每个对话固定绑定一个项目和一个专家           |
| 专家 | 提示词、技能、公司分配的模型与工具能力         | 沿用现有分配和权限，不因加入项目扩大权限     |

同一项目下的对话共用项目文件，但各自保留聊天记录、执行检查点和审批状态。项目不会自动合并不同专家的聊天上下文或个人记忆。

### 1.1 首次打开项目

1. 点击“打开项目”，通过系统原生选择窗口选择文件夹。
2. 默认使用文件夹名作为项目名称，保存项目并切换到该项目。
3. 点击“新建对话”，选择专家，开始处理项目中的文件。
4. 当前项目与最近使用的专家在同一企业账号、同一电脑下保存，重启后恢复选择。

新建文件夹可通过系统选择窗口提供的能力完成，不另做文件管理器。

### 1.2 后续新建对话

1. 默认沿用当前项目及该项目最近使用的可用专家。
2. 发送第一条消息前，可以更换专家或选择其他项目、打开其他文件夹。
3. 选择其他文件夹表示切换或创建项目，不修改旧对话所属项目。
4. 对话创建时确定项目归属；已有消息或执行记录的对话不提供任意更换项目或专家的入口。
5. 需要其他专家时，在当前项目新建对话；已有模型、推理与审批设置继续按对话保存。

### 1.3 切回历史项目与对话

- 侧栏以项目为主，按需展开项目下的对话；对话显示专家名称和执行状态。
- 打开项目时恢复上次查看的有效对话；没有对话时展示新对话入口。
- 从搜索、通知或历史入口打开对话时，自动定位所属项目和专家。
- 项目目录不可用时允许查看历史，发送任务前提示重新定位原目录；不得自动改用当前项目或默认目录。

### 1.4 保留专家列表入口

专家列表继续用于查看和选择专家。从专家列表点击开始对话后，默认带入当前项目，也可以选择其他项目。两个入口共用相同的项目和对话绑定逻辑。

项目列表需要聚合该员工不同专家的对话，不再只以当前专家的会话列表作为项目导航的数据来源。旧服务器历史和尚未定位的本机历史保留独立入口。

## 3. 本期范围与边界

本期包含：

- 保存、选择和切换多个本地项目，记住当前项目。
- 新对话选择项目与专家，同项目不同对话共用文件。
- 项目侧栏、跨专家对话列表、当前项目和专家的明确展示。
- 切换项目或查看其他对话时，已开始的任务保持原目录、原专家和原执行状态。
- 按项目处理文件预览、附件导入、成果展示和打开文件位置。
- 重启恢复、目录不可用提示、旧对话兼容及新旧组件能力协商。

本期不包含云端文件同步、跨电脑接管项目、Git worktree、自动合并专家上下文、同一对话动态更换专家和新的团队协作调度系统。

本期采用以下执行边界：

- 同一项目同时执行一个任务，其他对话可以查看。再次提交时给出明确的忙碌提示，不额外建设持久排队系统。
- 不同项目复用现有本机总并发上限，目前为 4；不因项目数增加而放大上限。
- 待审批任务仍占用项目执行位置；结果未知的任务须先核对，不自动重放。
- 相同实际目录复用已有项目。父子目录或目录别名存在重叠时，执行互斥按实际路径判断，避免两个项目同时修改重叠文件。

以上限制用于控制共享目录的写入冲突。后续如需同项目多个专家同时执行，再单独设计文件冲突和成果归属规则。

## 4. 数据与接口设计

### 4.1 稳定项目身份

新增稳定、不透明的 `project_id`。项目不使用目录名作为唯一身份，也不使用每次登录重新签发的 `device_id` 作为永久归属。

| 数据位置           | 保存的内容                                      | 约束                                                   |
| ------------------ | ----------------------------------------------- | ------------------------------------------------------ |
| 本机原生端项目登记 | 项目 ID、目录映射、授权状态、路径修订、当前项目 | 按企业地址、员工和稳定安装身份隔离；原子保存           |
| 服务端项目元数据   | 项目 ID、所有者、安装归属、展示名称、时间等     | 用于归属校验和列表展示；不要求上传完整本机绝对路径     |
| 对话项目关联       | 对话 ID 与项目 ID                               | 创建空对话时即可保存，不依赖第一次任务领取才产生       |
| 本机任务记录       | 项目 ID、实际根目录快照、路径修订、既有任务信息 | 执行、恢复和文件路由使用任务绑定，不读取当前选中的项目 |

沿用现有账号安装 token，不能为每个项目重新生成安装身份，否则既有会话可能被误判为另一台电脑的项目。重装或其他电脑上的同名目录不自动接管原会话。

本机路径由原生文件夹选择窗口确认。网页桥接传递项目 ID 或对话 ID，原生端解析登记信息；网页不能靠传入任意路径完成授权。Windows 大小写、目录别名及实际路径去重需按平台处理。

### 4.2 项目与对话接口

接口名称在实施时按现有路由风格确定，需要覆盖以下契约：

- 创建、列出、重命名项目元数据，并校验员工归属；本机目录授权由原生端负责。
- 创建对话时携带 `project_id`，继续校验所选专家属于当前员工且仍可用。
- 按项目分页读取跨专家的对话，返回 `project_id`、`agent_id`、标题、时间和执行状态。
- 对话详情、历史恢复与分支对话返回项目归属；分支继承原项目和专家。
- 不通过前端逐个专家拉取全部会话再拼接项目列表；服务端批量查询并保留分页。
- 项目创建与本机登记支持幂等重试；失败时保留可恢复的登记状态，不留下可执行的错误目录绑定。

新增数据库结构采用增量迁移，并同时提供 SQLite 与 PostgreSQL 版本。SQL 放在 repo，业务归属与迁移规则放在 infra 服务，HTTP 层保持参数校验和结果映射。

### 4.3 项目生命周期

- 项目名称可以修改，不影响实际目录或对话绑定。
- “从列表移除”和“撤销本机授权”分别定义行为，均不删除用户项目文件。历史对话保留可查看入口。
- 已有活动、待审批或结果未知任务时，不允许直接修改其目录绑定；需要先停止或核对任务。
- 原目录移动后，通过原生选择窗口明确重新定位，保存路径修订；新任务使用新修订，旧任务和旧成果保留原路径信息，不以同名文件推断已完成迁移。
- 专家被停用或撤权后保留历史，阻止继续使用该专家提交任务；同项目可以选择仍有权限的专家新建对话。

## 5. 本地运行时改造

优先保留每个企业账号一个本地运行进程，在进程内按任务使用项目目录。项目数量增加不应导致每个项目启动一套 Python 工具和连接。

1. 将运行时的账号连接、工具初始化与具体项目目录分开。账号退出、切换企业及身份过期仍按现有规则停止账号运行时。
2. 启动任务时，由原生端解析对话绑定的项目，核验授权与目录修订，再传入可信的任务目录上下文。
3. `ProjectBackend`、Shell 的 `cwd`、文件工具和成果处理全部使用任务固定的项目根目录。不得使用进程级 `os.chdir()` 切换项目。
4. 新模式直接在选择的项目根目录执行；旧模式继续按记录使用原有对话子目录，不通过全局替换路径实现迁移。
5. 项目切换只改变界面选择，不关闭运行进程、不撤销其他项目授权，也不清空其他任务的成果回执。
6. 取消、审批、追加指令、恢复核对和事件投递继续以对话及任务 ID 路由，避免操作当前页面以外的错误任务。
7. 项目执行互斥在原生可信目录解析后建立，由本地运行时统一执行；权限撤销或退出后旧请求不能继续写回。

检查点、操作日志、凭据、技能缓存和待同步数据继续保存在项目目录之外。项目文件共享不改变这些数据按账号、专家、对话和任务分别保存的规则。

## 6. 文件、附件与成果处理

这是与目录切换同时交付的范围，不能只让消息执行支持项目。

- 预览、打开位置、上传成果和附件导入请求携带所属项目或对话信息，按相应授权目录校验，不根据当前页面选择推断文件归属。
- 从项目 A 切到 B 后，A 的任务回执仍写入 A；打开 A 的历史成果也按 A 校验。
- 将 A 的文件作为 B 的附件时，分别核验来源和目标，再按现有明确发送或导入操作复制；原文件不移动。
- SHA-256、真实路径、目录边界和迟到请求校验继续生效；文件变化或已移动时给出明确反馈。
- 项目文件面板与 `@` 文件引用使用当前对话的本地项目来源，不能继续指向服务端专家工作区。
- 共用项目目录后，避免把其他对话或用户手工修改的文件自动认定为当前轮成果；显式发送文件与任务成果回执保留来源。
- 新项目任务不在执行前后扫描整个目录计算文件哈希，只记录本轮文件写入、编辑和媒体生成工具实际写入的文件，以及显式发送的文件；Shell 生成的成果通过 `send_local_file` 交付。旧单目录模式保留原来的差异扫描。
- 本地文件面板跳过 `.git`、依赖等目录，单次最多检查 10,000 个条目、返回 500 项，搜索深度最多 16 层；文本预览最多 256 KiB，交付文件仍按现有大小和哈希规则校验。代表性大型项目的真机耗时另行验收。

## 7. 旧数据与组件兼容

### 7.1 旧目录和旧对话

1. 保留原来的单目录配置及账号安装身份，新增登记格式使用独立结构，避免旧格式被直接覆盖后无法识别。
2. 根据本机任务记录中的 `project_path` 识别旧对话实际目录；同一路径只登记一次。旧对话先显示在历史项目区域，可使用会话标题辅助命名。
3. 旧对话继续使用原来的物理子目录，既有文件、会话编号和检查点不搬动、不重写。
4. 不能把旧全局父目录直接绑定给所有旧对话，也不能仅凭当前父目录推测所有历史路径；缺失可靠记录的会话保留未定位状态。
5. 用户可以在已定位的旧项目里新建对话，共用该项目已有文件；新打开的项目直接使用选中的目录。
6. 迁移必须可重复执行，中断后可继续；保持原先明确移除目录的选择，不自动重新授权或创建默认项目。

### 7.2 服务端、桌面外壳、前端和工具包

通过显式能力协商启用多项目功能，覆盖四者不完全同步更新的情况：

| 组合                          | 预期行为                                                                           |
| ----------------------------- | ---------------------------------------------------------------------------------- |
| 新服务端 + 旧客户端           | 保留原单目录和旧任务协议，不强制旧客户端识别新项目                                 |
| 新客户端 + 旧服务端或旧工具包 | 提示当前组件缺少多项目能力；已有旧流程是否可用按协商结果判断，不静默执行到错误目录 |
| 全部支持多项目                | 启用项目列表、新建绑定及按项目执行                                                 |
| 其他电脑查看项目历史          | 可以按已有权限查看，显示本机目录未关联；不自动获得原电脑文件或执行权               |

不能将 `project_name = thread_id` 的旧约定直接改成任意绝对路径，也不能为了兼容而取消既有安装归属检查。新增协议能力不自动触发产品版本升级。

## 9. 定向验证清单

### 9.1 用户场景

以下为安装包真机验收清单，尚未执行，不用模块测试替代勾选。已完成的自动化和浏览器组件验证见第 11 节。

### 11.2 已实现的完整链路

- schema 31 同时提供 SQLite/PostgreSQL 迁移；服务端保存项目元数据和固定的对话项目关联。创建空对话时即保留本机执行归属，项目创建与绑定支持事务及幂等重试。安装 token 不进入查询 URL 或返回数据，项目目录路径不作为服务端项目元数据上传。
- 员工原生桥接接通项目登记、选择、改名、移除、撤权、重新定位、分页查询、新对话及分支。服务端、Python worker 和客户端协商 `multi_project_v1`；未协商成功时不向错误目录静默降级。
- 账号运行时可以在没有选定项目时初始化。每次任务固定项目 ID、真实根目录和路径修订；切换侧栏不重启运行时、不改变既有任务目录。服务端按项目、本机按真实目录重叠关系互斥，结果未知的任务也阻止冲突执行。
- 本机项目按企业账号隔离并原子保存。重复选择同一目录复用项目；更名、移除和撤权保留文件及历史；重新定位保留项目 ID，要求旧任务已结束并完成同步。旧任务按最新有效回执的原始路径导入，不搬文件、不推测目录、不重新授权已撤销的项目。
- 项目侧栏聚合不同专家的会话并分页，显示所属专家和任务状态；保留“专家与历史会话”入口。新对话默认当前项目，草稿按项目和专家隔离；历史会话及分支继续使用原项目和专家。
- 文件面板、文本和图片预览、打开位置、`@` 文件引用、成果上传与附件导入均使用原生解析的所属目录。跨项目附件复制分别校验来源和目标，成果不会因侧栏切换改用其他目录。迟到的账号、授权和目录修订响应被丢弃。
