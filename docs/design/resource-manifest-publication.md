# 资源快照落盘与发布边界

员工实例准备和桌面导出使用的定义、技能及附件固定为同一份不可变 manifest。schema 28 建立员工运行快照；schema 29 进一步增加隔离 worker 的管理员源发布指针。单体继续使用 `legacy_content` 内容校验，产品版本不变。

## 隔离 worker 的发布路径（schema 29）

只有 PostgreSQL 分角色模式且 Docker 工作区隔离有效时启用 `published_source`。管理员工作区/技能/技能包、专家初始化及复制、资源源切换、插件管理和源专家的工具调用进入同一个发布门；源初始化等待完成，后台重载产生的文件写入在发布前排空。SQL 触发器使离线的专家定义或技能包修改使版本失效；分角色模式拒绝其他离线管理 CLI 直接修改，正常管理经在线入口执行。

写入发生在草稿工作区，发布时完整捕获并复核两次，将定义、技能和附件复制到工作区之外的不可变对象存储，再使用来源代次及脏修订 CAS 发布。提交同时验证当前源账号和 worker 的数据库租约/主节点身份。读路径复用已发布 manifest，仍实时核对员工、源策略、分配与 Go 部门授权。工作区外部修改是草稿，必须成功发布才能成为员工可用资源。

保存失败、源切换失败或磁盘错误不发布半成品；结束 editing 状态并保留旧 manifest，下一次显式成功保存才发布该草稿。成功的 HTTP 响应在发布完成后返回，包含请求的后台写入。启动时恢复崩溃遗留的 editing 状态。该边界已有临时数据库/文件系统及 ASGI 定向验证，尚待实际 Docker 的所有写入入口联调。

角色档位的单次资源包上限分别为 64 / 128 / 256 MiB；单体继续为 512 MiB。文件数、单文件与定义限制同下文。源目录和员工工作区不能挂载宿主 manifest 存储；只读权限本身不等于对持有 Docker/宿主权限的管理员形成安全隔离。

以下保留单体 `legacy_content` 路径及早期实施边界，不能据此关闭旧源的实时内容检查。

## 当前数据流

1. 核对当前员工、专家分配及 Go 部门归属，读取该实例已有 manifest 代次。
2. 读取管理员定义和员工获准的技能；内容摘要直接从本次保留的字节计算，不使用前一次扫描的摘要标记另一次读取。
3. 资产按 SHA-256 写入 `company-runtime-skills`。先写同目录临时文件、同步数据、设为只读，再以排他链接发布最终散列名。已有对象先校验后复用，不重写；并发写入相同内容只会留下一个完整对象。
4. 再次核对授权和真实源内容，变化则返回冲突。生成包含员工/实例/源身份、修订、专家字段、定义正文、运行参数和资产清单的 manifest；不包含管理员个人文件、供应商配置或真实 Key。
5. manifest 文件落盘后，事务核对当前分配、源策略、部门代次、源实例身份和账号可用性，通过 CAS 更新 `managed_resource_manifests`，同时写入 `managed_resource_outbox`。失败时二者一起回滚；旧请求不能覆盖已提交的新指针。
6. 服务端准备从同一捕获结果复制定义和技能。桌面导出也使用其中的管理员定义，员工 USER、MEMORY 仍来自自己的工作区。任务已有的事务保存专家响应及 `resource_manifest_sha256`；资产下载继续按该任务的授权清单核对散列。

重复准备相同内容不增加代次或 outbox，也不改写共享源版本。实例删除后重新使用保留的实例 ID，代次继续递增。每次准备完整快照最多并行 2 项、最多容纳 8 项，避免同时保留过多文件字节。

技能清单与附件均保留完整字节，单文件最多 64 MiB；单个员工快照最多 512 MiB、20,000 个文件。定义文件最多 262,144 个字符，超出时拒绝生成快照，不能把截断片段当作完整定义。

## 故障与保留

| 情况 | 行为 |
| --- | --- |
| 写入/同步磁盘失败 | 不提交新的 manifest 指针，已有实例文件保持原状；已完整落盘的散列对象可能作为未引用文件保留 |
| 重复或并发生成同一对象 | 校验已有散列后复用，禁止覆盖坏文件 |
| manifest 写完但事务失败 | 指针和 outbox 不变；已完成对象保留，不能被误当作已授权发布 |
| 生成期间发生撤权或部门变更 | 当前权限/修订核对失败，拒绝提交或下一次受控调用 |
| 存储内容损坏、丢失或变为软链接 | 准备失败或下载返回校验冲突，不向运行时发送替代字节 |
| 进程遗留临时文件 | 启动时清理超过 24 小时的 `.pending-*` 普通文件；新临时文件和散列对象不删除 |
| 备份恢复 | 数据库包含指针和 outbox；资产目录只导出正式散列对象，恢复前校验摘要 |

完整但未被引用的对象、旧 manifest、任务资产和 outbox 暂不自动删除。后续垃圾回收必须定义引用保留期，并与正在发布和领取任务的进程协调，不能仅凭文件年龄删除。outbox 目前是可按递增 ID 补读的持久记录，尚未接入跨进程通知消费者。

只读文件权限用于防止意外写入，不能隔离持有同一宿主账号权限的进程。源发布目录尚未完成与可执行工作区的权限隔离，不能因此开启版本读取快速路径。

旧的可写缓存首次复用时通过可写句柄同步并设为只读，已密封对象只校验复用。这样也避免向只读文件句柄请求 Windows 文件刷新；其写权限要求见 [Microsoft 文件刷新接口说明](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-flushfilebuffers)。本批未执行 Windows 宿主验收。

## 保存时发布仍需迁移的写入口

| 写入口 | 当前行为与后续要求 |
| --- | --- |
| 工作区编辑、文档保存、上传、删除、移动、归档导入 | 仍写活动工作区；需统一暂存提交并处理多文件操作失败 |
| 技能创建、编辑、安装、导入、复制、启停、挂载 | 需将文件集和启用/挂载元数据作为一个源版本提交 |
| 技能包存储及清单编码修复 | 仍有直接宿主文件写入；需受管写入和只读发布视图 |
| 专家字段、初始化、复制及删除 | 需在源发布事务中纳入身份、定义和删除标记 |
| Agent 文件工具、命令及外部工作区修改 | 需隔离草稿与已发布内容；受控保存自动提交，直接文件操作不能改写发布目录 |

完成这些入口及权限隔离之后，才能增加源级完整 manifest 和源版本，令配置状态只查询版本；员工级 manifest 可以继续作为已选资源的固定运行凭据。管理员正常保存保持自动同步，不增加必须手动执行的发布步骤。迁移前仍检查真实定义、技能脚本和附件，文件监听或 TTL 不能替代下一次受控调用的授权校验。
