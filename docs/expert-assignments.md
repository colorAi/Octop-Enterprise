# 给员工分配专家和技能

管理员在“管理 → 用户 → 公司架构”中维护部门可分配的资源，再为每位员工勾选专家和额外技能。资源复用选定管理员已经安装的内容，不需要另外建立或发布企业库。

## 设置顺序

1. 在原“专家”和“技能”入口安装、维护所需资源。
2. 在公司架构的“专家资源来源”中明确选择管理员账号并保存。只有该管理员已启用的专家、其专家中的有效技能，以及由该管理员安装的技能包成为候选。技能创建、安装等管理技能不作为员工候选。
3. 在部门分组内点击“管理可用专家”和“管理可用技能”，设置部门范围。固定保留“未分配”范围；未分配员工也可以明确配置资源。增加部门资源不会自动授权所有成员。
4. 在员工行点击“专家管理”“技能管理”，或职位旁的设置按钮。抽屉包含“专家权限、技能权限、基本设置”三个页签。
5. 在“专家权限”选择该部门允许的专家；在“技能权限”选择额外技能；保存后生效。默认技能和专家提供的技能不需要重复选择。

“查看已安装资源”展示当前候选，并提供原管理入口。这里还可设置明确的系统默认技能。系统内置不代表默认对员工开放；没有配置默认清单时显示零项。

公司架构先显示人员，资源目录单独加载。部分查询失败时保留已有内容，并提供重试；资源目录尚未就绪时不能提交资源编辑。出现“部门状态待核验”时，打开员工编辑器会重新核对当前部门及分配。页面展示不代替保存和执行时的权限检查。

员工只能从本部门的范围内获配资源，不继承父子部门的范围。选择多位同部门员工后，可批量替换专家或额外技能分配；另一类资源保持不变。空选择表示收回对应资源，保存前显示替换提示。

只有实际管理员可以修改资源分配，拥有管理菜单的普通员工不能给自己增加资源。来源账号停用、删除或失去管理员角色后，新的分配和使用会被拒绝。更换来源前需清空旧员工授权、部门范围和默认技能，不通过名称接续授权。

## 三类技能

| 来源 | 如何获得 | 如何收回 |
| --- | --- | --- |
| 系统默认 | 管理员在已安装资源中设置明确清单 | 修改默认清单 |
| 随专家提供 | 使用已获配专家时提供该源专家当前启用的技能 | 收回该专家或调整其技能 |
| 额外分配 | 从员工所在部门的技能范围内逐项选择 | 取消员工选择、收紧部门范围或调岗越界 |

抽屉汇总技能并合并重复来源。实际运行某个专家时，只下发该专家的必要技能、系统默认技能和该员工额外获配的技能；不会加载员工其他专家的专属技能。技能包按其中的具体技能选择，不会因为选中一项就下发整包。不同来源存在同名但内容不同的技能时，会提示冲突，需管理员调整选择。

技能授权不额外授予模型、底层工具、连接器、知识库或凭据权限，现有的员工权限和配额仍然生效。

## 员工基本设置与调岗

“基本设置”维护所属部门和职位，支持选择已有职位或输入新职位。姓名在用户管理中维护。保存调岗时提示将收回的越界资源，只保留新部门仍允许的专家和额外技能，不自动增加新部门资源。

部门资源收紧会清除已知的越界选择，随后重新加入资源不会恢复已清除的授权。正常调岗绑定目标部门当时的资源范围；准备期间的移除也会计入，不通过“移除再添加”恢复资源。后台或其他入口发生无法确认中间过程的调岗时，会保守清除旧选择，管理员可重新分配。

组织服务使用成员修订与操作回执，控制面在执行前读取当前部门。调岗提交结果未知时暂时阻止新的受管执行，并查询或取消原操作，避免迟到请求绕过权限。组织服务不可用时不启动无法确认权限的受管调用。

批量调岗逐人保存并报告部分失败；出现部分完成提示后，刷新确认当前状态再重试。

## 已有账号与数据

已有员工保持原使用方式，直到管理员明确保存该员工的资源设置。来源设置后创建的新员工默认等待分配。管理员可关闭“仅使用分配的专家”恢复员工原有自主使用方式；此时本页显式分配清空。

员工首次使用获配专家时生成独立实例，保留自己的会话、记忆和文件，管理员个人资料与凭据不会复制给员工。实例初始化只复制管理员维护的定义文件，不复制完整技能目录、子代理或整包挂载。技能按当前启用状态和具体授权生成运行快照。

管理员调整专家名称、说明、提示词、定义文件或技能内容后，员工可以通过“更新配置”同步已有实例，不需要重新分配专家。同步覆盖管理员维护的定义和批准的技能，保留员工的 USER.md、MEMORY.md、会话、检查点及个人工作文件。技能和定义目录由管理员维护，员工不能通过技能管理、工作区文件操作或整包导入修改它们；未授权技能也不能通过直接传文件路径读取。

分配保存会通知客户端检查配置。提示词、定义文件和技能脚本等内容变化也纳入配置修订，客户端在前台每 25–35 秒、重新聚焦和重连时检查；连续通知会合并处理，查询期间收到的新通知会在结束后再检查一次。离线期间错过的变化会在再次打开客户端时提示。点击“更新配置”会先在服务端应用最新定义和技能，再刷新页面，无需重新安装客户端。正在执行任务时会提示稍后更新，避免替换运行中的服务端实例；即使没有点击更新，下一次任务也会先同步并检查当前授权。

源内容或授权变化后，旧运行快照不能继续取得新的受控调用授权；企业桌面会在任务状态检查中请求取消旧任务。更新或撤权不回滚已经发出的外部请求和本机命令。源技能删除、停用或依赖缺失时，不通过旧缓存继续执行。

服务端准备和企业桌面导出的管理员定义、技能与附件会固定在同一份已校验的快照中。生成校验时发现源内容变化会拒绝本次快照；文件缺失或损坏时不会下载替代内容。正常配置更新仍按上述流程自动生成快照，无需额外发布操作。

停用员工后仍可清空其分配，不需要临时启用账号。收回使用权会请求取消运行任务，拒绝后续新执行。已发出的外部请求或已开始的本机命令可能需要时间停止，取消不会回滚副作用。原会话和文件不删除，必要的最终状态、事件和检查点仍可上报。

企业桌面使用员工的操作系统账号运行工具。本功能控制服务端授权和技能下发，不提供员工电脑的进程沙箱或技能缓存防篡改。员工旧安装包不自动重建；新的管理页面由服务器提供。

## 保存冲突

保存校验员工、来源、部门资源和成员修订。其他管理员修改后，旧表单会提示刷新，不覆盖新设置。批量资源分配在同一事务保存，任意一位员工冲突时整笔拒绝。基本信息和资源分属组织服务与控制面；部门已保存而职位或权限保存失败时，会提示部分完成并尝试刷新，旧表单不能再次提交。请求结果不确定时也需核对刷新后的部门、职位和权限。

## 管理 API

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/admin/expert-assignments` | 来源、真实技能候选、部门范围和员工分配 |
| GET | `/api/admin/expert-assignments/directory` | 不扫描工作区的分配展示，含批量部门修订及 `membership_status` |
| GET | `/api/admin/expert-assignments/catalog` | 独立加载专家及技能候选；携带来源修订，与人员分配按来源修订匹配 |
| GET | `/api/admin/expert-assignments/users/{user_id}` | 打开员工编辑器前核验权威部门并协调当前分配 |
| PUT | `/api/admin/expert-assignments/source` | 明确选择来源管理员 |
| PUT | `/api/admin/expert-assignments/departments/{scope_id}` | 部门专家和额外技能范围 |
| PUT | `/api/admin/expert-assignments/defaults` | 明确设置系统默认技能 |
| PUT | `/api/admin/expert-assignments/employees` | 同部门员工的完整资源选择，原子保存 |
| PUT | `/api/admin/expert-assignments/users/{user_id}/basic` | 部门、职位和成员修订 |
| PUT | `/api/admin/expert-assignments/users/{user_id}` | 兼容原专家保存接口，同样受部门范围校验 |
| GET | `/api/client-config/status` | 员工自身配置修订及待同步状态，不返回管理员定义正文 |
| POST | `/api/client-config/apply` | 应用当前员工获准的定义和技能；运行中任务需要先处理完 |

员工列表使用 `/api/agents`，首次使用仍调用 `/api/agents/{source_id}/private-instance`，返回员工自己的实例 ID。
