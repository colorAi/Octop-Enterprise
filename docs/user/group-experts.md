# 群聊专家

群专家在公司群、部门群和项目群中回答被 `@` 的问题，每群最多邀请 3 位专家。

## 部署条件

当前版本需要 PostgreSQL 和 **Web/Worker 分角色部署**，入口是 `docker/enterprise/compose.roles.yml`。基础模式和 `docker/enterprise/compose.yml` 企业单体模式均不支持群专家；单体模式的普通同事消息和群聊仍可使用。

服务端使用同一发行源码构建，主库 schema 为 36、通信库 schema 为 21。固定拓扑中的所有 Worker 必须运行并声明群专家协议 2。服务是否已就绪由运行状态和持续心跳判断，完成数据库迁移后仍需要检查。

全新部署先按[企业部署指南](../../docker/enterprise/README.md)准备配置、密钥和镜像，再按[分角色初始化与启动](../../docker/enterprise/ROLES.md#初始化与启动)使用同一资源档位执行完整命令。已有单体实例切换前备份两库、文件、配置和工作区，停止旧应用及其工作区容器；保留数据和密钥，不再运行 `prepare.py` 或 `octop init`。已有分角色 Worker 则先按[故障核对流程](../../docker/enterprise/ROLES.md#任务补读与故障核对)确认旧执行者停止，再创建新的启动代次。

## 启用与邀请

1. 企业管理员在“公司架构”中配置[专家与技能来源](expert-assignments.md#设置顺序)，并给员工分配需要使用的专家和模型。
2. 打开“公司架构 → 群管理”，选择目标群，配置“本群可用专家范围”。部门群的专家还需要属于该部门的可用专家范围。
3. 开启“启用本群专家”，选择专家并邀请。每群默认关闭。
4. 群主和群管理员也可以从群详情邀请专家，只能选择企业管理员已为本群开放的来源。

来源专家使用 `AUTO` 模型时，管理员需要先配置有效的企业全局模型。员工仍须有使用该专家和模型的权限；群管理员身份不会自动获得模型使用权。

## 提问和成果

- 在群输入框的 `@` 菜单中选择专家并输入实际问题，每条消息调用一位专家。
- 专家读取本次问题及至多一条直接引用的文字；不读取完整群历史、成员个人工作区或个人记忆。追问时引用上一条答复并再次 `@` 专家。
- 联网搜索、生图和生视频使用来源专家自身已开启的工具设置及企业服务。生成成果随群回复发送。
- 模型用量计入提问人的额度。调用失败时，合法的普通群消息仍会保留，可在原问题旁查看原因。

## 常见提示

| 提示或现象 | 检查方式 |
| --- | --- |
| 群专家功能尚未就绪 | 确认采用分角色部署；检查所有 Worker 的版本、运行状态、数据库迁移和通信服务。主 Worker 日志中的 `group expert heartbeat will retry` 表示能力心跳未成功。Python、Go 和 PostgreSQL 所在主机需要同步时钟。 |
| 企业管理员尚未为本群开启专家 | 管理员到“公司架构 → 群管理”打开本群开关。 |
| 没有可邀请的专家 | 检查来源管理员、已启用的来源专家、本群范围和部门资源池；等待授权同步完成。 |
| 已邀请但本人不能调用 | 检查本人群成员状态、发言权限、专家授权、模型授权和额度。 |
| 网页有功能，客户端没有 | 安装匹配版本的企业客户端，界面资源不会通过配置通知自动下载。 |

容器启动和健康检查通过后，仍应实际完成一次邀请、`@` 提问及回复查看。资源限额与维护命令见[分角色部署](../../docker/enterprise/ROLES.md)。
