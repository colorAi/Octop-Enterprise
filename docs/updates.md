# Octop Enterprise 更新说明

[English](updates_EN.md)

Octop Enterprise 由管理员从本仓库源码构建和升级。配置更新用于刷新权限、模型授权和功能配置；软件升级用于更新服务器、客户端界面及工具环境。

## 日常权限与功能配置

管理员保存员工角色、权限或策略后，系统自动通知对应员工。模型授权及其他功能配置保存后，可在左侧“管理 → 应用设置”中切换到“应用更新”标签，在“员工客户端配置更新”区域填写说明并发布通知。

员工收到“企业配置有更新”后，在没有任务执行或准备、等待工具审批、编辑本机消息、上传附件、未发送附件或排队消息、录音或转写、浏览器录制或回放时点击“更新配置”。应用刷新当前界面，保留站点登录状态和已保存草稿，无需退出客户端。服务器始终按最新权限校验请求，延后刷新不会继续保有已撤销的权限。手动隐藏的菜单不会因新增授权而强制显示。

这条通道适用于已经安装了配置刷新功能的客户端，且只应用当前代码已支持的权限、模型授权和功能配置。通知不会替管理员保存配置，也不会启用尚未部署的新功能；详情见[配置更新](client-config-update.md)。

## 服务器软件升级

当前采用管理员手动升级：

1. 阅读本项目目标发行的版本、兼容要求及数据库迁移说明，确认客户端是否也需要更新。
2. 等待任务结束，在维护窗口完成主库、通信库、文件、密钥和隔离工作区的完整备份，并验证可恢复。
3. 从目标源码构建新的基础应用、企业应用和通信镜像，使用独立标签或 digest，保留旧镜像与配置。
4. 停止应用与通信，运行新通信镜像的迁移命令，再启动新服务；主库迁移由应用启动执行。
5. 检查 readiness、登录、模型请求、消息附件和客户端本机任务，再恢复日常使用。

具体命令与回退条件见[企业部署与恢复](../docker/enterprise/README.md#升级与回退)。升级不运行 `prepare.py`，不重新执行 `octop init`，不更换已有通信密钥。产品内“系统备份”不等于企业全部组件备份。

网页用户刷新后可加载服务器已部署的新网页代码。员工客户端界面随安装包内置，单独更新服务器不会替换它的页面资源；客户端兼容要求见目标版本的发行说明。

## 员工客户端软件升级

内置界面、原生桥接、Python/文档/FFmpeg 工具环境变化，需要管理员提供匹配的新安装包。员工完成当前任务后按对应发行说明安装，必要时退出再启动程序。

发布者需要一起构建网页、桌面壳和匹配的离线工具 payload，并公布系统架构、校验值、签名与实机验证状态，见[桌面构建](../desktop/README.md)（English）。不支持用“更新配置”下发新的界面代码或原生程序。

本机项目保存在员工工作目录；安装与升级前仍应保留该目录、原有账号配置和任务回执。跨设备查看历史不会自动复制项目或接管运行中的任务。

## 更新来源

使用本仓库对应版本的源码和匹配客户端升级。`octop update` 与在线更新 API 在本发行版中禁用；上游同名 PyPI 包和个人版安装包不能用于企业版升级。客户端界面资源随安装包更新。
